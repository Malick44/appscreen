# AppScreen asset and license inventory

Reviewed: **2026-09-04**. Repository: this repository root.
Paths below are relative to that repository root. This is a read-only factual
inventory and launch-gate record, **not legal clearance**. It does not establish
ownership or permission where provenance is missing. No assets were downloaded,
licenses changed, or rights holders contacted during the review.

## Scope and evidence limits

- Inspected actual source files, packaged-file rules, installed direct dependency
  licenses, model GLB JSON metadata, and the hosted renderer request allowlist.
- Checked the running local SaaS server with read-only HEAD requests on
  `http://localhost:8001`. This establishes that server's exposure, not a deployed
  production image's contents.
- Consulted primary publisher/license sources on the review date. Sketchfab's
  direct pages returned HTTP 403; the Samsung listing and iPhone embed information
  below came from the search index of those primary pages. Indexed information
  is not proof of the downloaded binary's historical license.
- Did not build or inspect the final Linux image, audit every transitive/OS/browser
  component, validate commercial trademark/design rights, or determine which
  rights attach to particular exported device renders.

## Open launch gates

### 1. Samsung model: conflicting license records and unverified lineage

`README.md:201` credits mistjs and says CC BY 4.0. The matching indexed primary
[Samsung Galaxy S25 ultra listing by mistjs](https://sketchfab.com/3d-models/samsung-galaxy-s25-ultra-24dc6725f97f4590a6309e9a48129ff2)
instead states **CC Attribution-NonCommercial**. The search result was retrieved
2026-09-04 and reported a crawl roughly two months earlier; direct retrieval
returned 403.

`models/samsung-galaxy-s25-ultra.glb` contains a Blender glTF generator string,
but no author, source URL, copyright, or license metadata. The README links the
creator's profile, not the exact downloaded model. Consequently, the listing is
a material conflict to investigate, **not proof that the current listing governs
this old binary**. A valid earlier CC BY grant could remain relevant; no dated
download record, archived license, source hash, or separate permission was found.

[CC BY-NC's official terms](https://creativecommons.org/licenses/by-nc/4.0/deed.en)
restrict commercial use. Before including this asset in a paid product, establish
the exact binary's applicable permission or make an explicitly authorized
exclusion/replacement decision. Do not silently relabel it CC BY or CC BY-NC.

### 2. Application MIT notice missing

`README.md:198`, `package.json`, and the About modal at `index.html:2463` claim
MIT licensing. No root `LICENSE`, `LICENCE`, `COPYING`, or `NOTICE` exists in the
checkout. The [upstream YUZU-Hub/appscreen repository](https://github.com/YUZU-Hub/appscreen)
also advertises MIT, but its linked
[LICENSE path](https://github.com/YUZU-Hub/appscreen/blob/main/LICENSE) returned
404 when checked on the review date.

The [MIT license text](https://opensource.org/license/mit) requires retention of
its copyright and permission notices. The current README assertion and creator
credit are not a recovered authoritative notice. Resolve the copyright/notice
record with the appropriate owner; do not invent a copyright year or holder.

`Dockerfile.saas:25-33` copies neither the root README nor a license file, and
`Dockerfile.saas.dockerignore` excludes them from the context. The live server
returned 404 for `/LICENSE` and `/README.md`. Thus the README's model credits
also do not accompany the hosted package as a document.

### 3. Shipped artwork with no asset-specific provenance

The following have no asset-specific creator/source/license record in the
inspected repository:

- `img/laurel-simple-left.svg` and `img/laurel-detailed-left.svg`: both have only
  `Generated by AMDN` comments. `core/render.mjs:39` preloads them for the shared
  renderer, and `server/render-service.ts:34` explicitly permits them.
- `img/info.svg`: likewise only an AMDN generator comment; used by the editor.
- `img/icon.png`, `img/icon.ico`, `img/icon.icns`: bundled branding assets;
  `saas/index.html:12` uses `icon.png` as the SaaS favicon.
- `img/screenshot-generator.png`: README demo image, also copied and publicly
  reachable because the entire `img/` directory ships.

An application-level license may ultimately cover original artwork, but that
relationship and any third-party source material have not been established.
Missing provenance is not itself proof of infringement or absence of permission.

### 4. Browser-delivered notices need an explicit delivery path

**Local remediation after the initial audit:** `/third-party-notices` now links from
the public SaaS footer and displays the full installed Supabase MIT and bundled
Inter OFL texts. `/third-party/supabase-license.txt` maps only to the installed
Supabase LICENSE, with a `rel="license"` response link on its browser bundle;
the existing `/render/fonts/LICENSE.txt` serves the font notice as plain text.
Regression tests compare exact bytes and reject adjacent private package paths.
The page explicitly describes its coverage as partial. This remedies those two
delivery paths only; it is not an application, artwork, model or full dependency
clearance. The initial observations below describe the state before this change.

`server/app.ts:26` serves `node_modules/@supabase/supabase-js/dist/umd/supabase.js`
as `/saas/vendor/supabase.js`. The installed 214,101-byte UMD file contained no
copyright/license marker. Its MIT notice exists at
`node_modules/@supabase/supabase-js/LICENSE` (copyright 2020 Supabase), but that
path returns 404 from the web server, and no browser third-party notice page was
found. Retention inside the container does not demonstrate that the browser copy
is accompanied by the required notice. Include the applicable notice in a
reviewed browser-delivery arrangement; do not expose arbitrary `node_modules`.

The interactive editor additionally fetches Lucide SVGs from
`lucide-static@latest` (`app.js:1316`). No local Lucide/Feather notice bundle was
found, and the downloaded SVGs were not inspected in this audit. Pin/inventory
the actual assets and preserve their applicable notices. The
[official Lucide license page](https://lucide.dev/license) identifies ISC licensing
and a list of Feather-derived icons under MIT; it is not accurate to describe
the whole set as one undocumented application asset.

[embed for the exact same model ID](https://sketchfab.com/models/5b7b35513a154ac69619dc2b2fe15686/embed)

confirmation, rather than replacing the binary's supplied attribution blindly.

model-credit/source/change notice in the hosted About screen. Review attribution
delivery for both the model distribution and applicable exported material.
[CC BY 4.0 section 3](https://creativecommons.org/licenses/by/4.0/legalcode.en)
requires supplied attribution/license information and modification indications
when sharing, allowing a reasonable form for the medium. The license does not
grant patent or trademark rights or establish endorsement.

## Software and container notices

- Interactive editor (`index.html:74-79`): JSZip 3.10.1 from cdnjs; Three.js r128
  and its GLTFLoader/OrbitControls from cdnjs/jsDelivr. Those remote response
  headers/notices were not downloaded or inspected. Three.js r128 uses
  [MIT](https://raw.githubusercontent.com/mrdoob/three.js/r128/LICENSE).
  `node_modules/jszip/LICENSE.markdown` explicitly allows choosing MIT **or**
  GPLv3; using JSZip does not by itself establish a GPL-only requirement.
- Installed direct package license files are present: MIT for Fastify and its
  two plugins, MCP SDK, Supabase, jose, pg, pg-boss, Stripe, tsx, zod and types;
  BSD-2-Clause for dotenv; Apache-2.0 for OpenAI, sharp, Playwright and TypeScript;
  dual MIT/Apache for the Tauri CLI. Playwright and TypeScript also include NOTICE
  files. `npm ci --include=dev` retains these files in the SaaS image, including
  development dependencies. Preserve relevant license/NOTICE files when changing
  packaging; [Apache 2.0 section 4](https://www.apache.org/licenses/LICENSE-2.0.txt)
  specifies redistribution conditions.
- `package-lock.json` contains 286 non-root package entries, including alternative
  operating-system/CPU packages. This is **not** the number installed in any one
  image. It includes LGPL-3.0-or-later libvips packages; the installed macOS ARM
  package's `README.md` lists additional library licenses, including MPL and
  LGPL. [The upstream libvips packaging project](https://github.com/lovell/sharp-libvips#licensing)
  distinguishes script licensing from the prebuilt libraries' various licenses.
- `Dockerfile.saas:18-23` installs Chromium, Playwright dependencies, Node/Debian
  packages and tini. This audit did not examine their final Linux binary notices,
  source availability or redistribution obligations. Do not claim that retaining
  npm licenses is a complete container-license audit, or that all dependencies
  are MIT. Internal hosted use and distribution of a container/binary need to be
  evaluated against the actual applicable terms.

## Hosted versus local distribution boundary

`Dockerfile.saas:28-33` copies `render/`, `saas/`, all of `img/`, both `models/`
GLBs and the legacy editor files. `server/app.ts:30` allows public files under
`models/` and `img/`. On the review date, live HEAD requests returned:

| Path | Status | Relevant result |
|---|---:|---|
| `/models/iphone-15-pro-max.glb` | 200 | 568,516 bytes, `model/gltf-binary` |
| `/models/samsung-galaxy-s25-ultra.glb` | 200 | 2,247,560 bytes, `model/gltf-binary` |
| `/render/fonts/LICENSE.txt` | 200 | 4,380 bytes, `application/octet-stream` |
| `/saas/vendor/supabase.js` | 200 | 214,101 bytes, JavaScript |
| `/LICENSE` | 404 | No application-license route/file |
| `/README.md` | 404 | Root README/credits not exposed |
| `/node_modules/@supabase/supabase-js/LICENSE` | 404 | Package license not browser-accessible |

The worker's narrower request allowlist (`server/render-service.ts:29-38`)
permits only the render page, template module, core modules, Inter WOFF2 and the
two laurel SVGs. `core/render.mjs:65` explicitly rejects 3D scenes. Therefore:

- The worker does **not** use the two 3D models, Three.js, Google Fonts or Lucide.
- The hosted interactive editor and container **do** ship the GLBs. Worker
  restrictions do not make them local-only or remove distribution concerns.
- Tauri icons under `src-tauri/icons/`, `.playwright-mcp` screenshots and test
  fixtures are excluded by `Dockerfile.saas.dockerignore`.
- The legacy `Dockerfile` separately copies all models/images and does not copy
  the root README/license either. The Tauri copy script is a different packaging
  path and was not treated as the SaaS image.
